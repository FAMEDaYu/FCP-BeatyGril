## 自动跟随与脸型修复

### 识别和转脸

当前使用 Apple Vision `VNDetectFaceLandmarksRequestRevision3` 与 `VNRequestFaceLandmarksConstellation76Points`。实时渲染自动检测并关联主要人脸，结合防跳范围、关键点稳定、失检保持和几何历史；不需要先点击分析。多人模式另走多人几何处理。

目标插件的静态证据支持 Vision 点阵与局部二维变形，已检查的瘦脸路径没有证明存在显式 yaw 切换或完整 3D 姿态模型。侧脸适应主要来自轮廓与五官点随姿态改变，不能宣称已确定某个第三方神经网络或完全恢复原版模型。证据入口见[脸型与转脸分析](analysis/脸型变形与转脸分析.md)和[自动跟随报告](analysis/auto-follow-report.json)。

本项目几何历史只取当前请求之前的近时记录，原版还存在近未来历史分支；冷启动、热缓存、乱序渲染、同尺寸换源和多人交叉仍有差异边界。旧离线分析字段保留兼容，但当前新面板的渲染统一使用实时自动跟随。

### 已完成的五项局部算法

| 控制项 | 当前实现 | 防止回归的要点 |
| --- | --- | --- |
| 瘦脸 | 76 点、17 组轮廓到鼻部或瞳孔锚点的局部逆向采样 | 不恢复整脸框水平挤压；保留尺寸增益、组顺序和逐步 clamp |
| V 脸 | `69→39`、`65→35`、`70→26`、`64→34` 四组下颌到外唇局部位移 | 新版 2.4.0 使用 0.065 系数、无旧尺寸增益；两瞳孔保持不动 |
| 下巴 | `68→38`、`67→37`、`66→36` 三组局部位移 | 正值上收、负值延伸，保留正负不同系数 |
| 下颌骨 | 六组相邻轮廓半径的顺序局部位移 | 半径来自相邻轮廓点，方向锚点为 P29；不能同时求和替代逐步更新 |
| 短脸 | P62 至 P72 的下半脸闭合区域，沿 P46−P48 鼻梁轴位移 | 正值收短、负值延长；不是太阳穴区域或脸框纵向压缩 |

此前四项沿用由实际图像像素尺寸计算的增益；V 脸对齐新版目标，不带该额外增益。完整合法 76 点缺失时，五项安全直通，不退回猜测的脸框场。图像与磨皮、肤色、牙齿、眼睛蒙版共用几何变形路径，避免效果与蒙版错位。

**仍为近似实现的四项：大眼、窄脸、颧骨、小头。** 原版完整链为 `thin → narrow → V → jaw → cheek → chin → short → small-head → eyes`，本项目尚未完全恢复整条组合链的数学及顺序。用户单项验收不代表所有参数组合逐像素等价。V 脸修复见 [下颌区域分析](analysis/V脸下颌区域修复.md)。详细索引、系数和独立数值场验证见[下巴与坐标分析](analysis/下巴与坐标分析.md)、[短脸与下颌骨分析](analysis/短脸与下颌骨分析.md)。

### 坐标约定

宿主 CI/IOSurface 链统一按 Y 向上处理；归档坐标标记为 `hostCoordinateSpace=iosurface-ci-y-up-v1`。不要仅看到 `TOP_LEFT` 标志就再翻转图像。局部几何中需要的归一化 Y 向下 UV 在同一 kernel 内成对转换，不改变宿主图像方向。

旧无标记分析档案不能靠补字符串伪装为新坐标。涉及位置的修改应同时检查非零 extent、图像宽高比、真实侧脸、歪头、正负参数和上下原点标签。历史“下巴作用在眼睛”“短脸和下颌骨作用在太阳穴”的问题已有相应修复，不应再用移动检测框来掩盖坐标或点索引问题。

## 面板与连续预览

界面由 AppKit 自绘磨皮、美白、瘦脸卡片及原生输入控件构成。FCP 模板只发布自定义面板 210 和两项署名信息，手动分析和多余平铺参数已隐藏；隐藏参数 ID 与旧归档仍须保留，以免破坏工程兼容。

面板交互必须在真实视图对应的 **宿主 action 内** 获取读写接口，不能缓存接口后在 action 外使用。每个发生变化的拖动步进都要在松手之前完成自己的 action；把整次拖动包在一个直到 mouse-up 才结束的 action 中，会再次造成松手后才更新。重复相同步进可去重。

`PGInspectorState` 保存完整且可安全归档的状态。未编辑面板时兼容旧文档参数，首次编辑采集当前设置；旧版各项独立关键帧曲线尚未自动迁移为新面板曲线。修改时同时检查数值 Return 提交、焦点切换、单项重置、宿主撤销和保存重开，不只看滑杆外观。

用户于 2026-10-22 明确确认“拖动中已持续更新”。该回复未指定宿主，覆盖至少一个原生宿主的按住拖动体验；宿主调度可能合并快速更新，不能写成每个鼠标事件必定显示一帧。
