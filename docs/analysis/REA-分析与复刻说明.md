## 已实现的功能

- 中频磨皮、强度、半径、高频细节平滑、锐化、五官保护及各大功能分组开关。
- 肤色提亮、色相、饱和度、均匀肤色；原色及自然白、冷白、暖白、红润白、小麦、古铜六个程序化风格。
- 牙齿美白和眼睛提亮，基于 Vision 面部区域构建软蒙版。
- 瘦脸、大眼、短脸、窄脸、下巴、V 脸、下颌、颧骨、小头和小头范围。
- 默认自动主要人脸几何跟随、矩形防跳、关键点稳定、失检保持和时间快照；默认外观蒙版保留整组检测范围，显式选脸与快速多人分别控制。
- 作为扩展提供三个独立跟踪目标，向前/向后分析，清除当前目标；精确 CMTime 数据持久化到宿主工程，可逆序和任意顺序读取。
- 蒙版阈值/柔度/边缘保护、皮肤/牙齿/眼睛通道预览与反转、包含几何变形的整体混合。
- 保留透明度、完整输入范围、非零图像原点与宿主上下原点；原生 FxPlug 参数可由宿主保存和制作关键帧。

## 复刻边界

本交付为功能相近的独立实现，算法结果存在以下差异：

1. 原版六个肤色 LUT 由独立颜色变换替代，风格名称接近，颜色值不相同。
2. 原版人脸网格/曲线位移采用本项目的平滑椭圆采样位移替代。各脸型权重和曲线、眼嘴软蒙版由本项目编写。
3. 皮肤支持区域使用 Vision 面部区域及独立的肤色/高通备用蒙版；原版完整皮肤分割、时间稳定和细部 mask 尚未等价恢复。
4. 本版最多保存三个独立目标、每次最多处理十六张脸。原版存在动态目标列表与旧版三目标字段，本次未完整恢复动态列表上限及全部分页操作。
5. 离线分析记录与默认实时自动跟随须分开比较。原版实时几何链已证实由Vision重检测、temporal主体关联、防跳范围、关键点稳定/保持及回看历史组成；OpenCV动态库与VNTrackObject备用方法的存在不足以证明它们驱动当前render主链。复刻版实时流程已按这些机制实现独立对齐，完整运动、多人交叉、遮挡与切镜仍需专项对照。
6. 界面使用宿主的分组滑块与开关；原版卡片面板的布局没有照搬。眼睛提亮在本版可用，所分析原版主链实际将该项输入设为零。

跟踪数据每目标保存上限为 64 MB；超过上限时保留此前已保存的数据并报告错误。长素材应分段分析。仅实际验证通过的内容计入完成；本说明中的未知项不因编译或离屏测试通过而自动消除。

## 自动跟随实现范围

默认渲染已加入独立实时几何状态，完全不依赖三个离线目标或分析按钮。默认主要人脸按面积与居中评分、前框矩形防跳和最近中心关联；选点变化重新种子，快速多人采用多人变形。外观与变形几何分开，默认皮肤/牙齿/眼睛蒙版仍覆盖检测组，图像与蒙版再共享同一变形几何；显式“只处理选中人脸”保留本项目原有外观单脸语义，此显式范围未证明与原版完全等价。

自有稳定公式将旧关键点映射到当前框，再以0.9及时间因子混合，异常眼轴翻转时保持重映射点。最多1200条、序列化估算16MB的纯几何缓存不保存图像；仅使用不晚于请求且0.35秒内的参考，连续保持可推进输出时间。精确CMTime、原始几何与上下文一致的重复渲染直接复用，不反复平滑。原版还可取近未来历史，本版选择past-only，因此不是完全相同时间策略。

当前框仍以检测为准，稳定主要影响自有warp所使用的眼部点；没有恢复原版77点网格全部稳定公式。没有真正素材来源ID，同尺寸换源只能靠时间/原始几何变化隔离，不能保证识别任意换源。首次冷启动、热缓存与首次乱序可能存在差异；锁和缓存不等于全局顺序无关。

## 默认自动跟随的补充分析

用户澄清后，已追查默认render→temporalFacePoints活跃路径，证据见 [自动跟随报告](auto-follow-report.json) 与 [REA证据包](rea-auto-tracking.json)。原版以Vision重检测当前帧，在默认非多人几何路径中自动选主要人脸；显式选点是重选种子，快速多人是独立分支。主要人脸初始化按面积与居中打分，其后将前框宽高扩到180%形成防跳矩形，在范围内选择最近中心。失检/无匹配可保持原点阵，关键点另有自适应稳定和轴向突变保护。默认几何单主脸不等于美肤/牙齿蒙版只能处理一人。

原版保存time/points/box历史，至多1200条并支持回看；平滑包含时间因子与约0.84–0.96的混合范围，完整组内公式及轴保护布尔组合未逐像素验证。原版存在近未来历史选择分支，所以不能宣称任意乱序严格确定。复刻将以独立公式实现机制，并限制读取当前时间之前的近时参考；该时间策略会比原版更保守，属于明确的实现差异。

本机原生观察：Motion中使用同一蓝发视频，原版UI默认多人关闭（单人）、防跳180%；启用检测框并调瘦脸/大眼后，播放时自动更新人脸框，没有先执行离线分析。此观察只覆盖该单人片段，不能替代多人遮挡与所有参数对照。

1.0.4已在Motion实际加载与不同播放头位置观察默认自动跟随输出；用户随后接管Motion/FCP自测，FCP该版自动跟随及显式OSC原生点击尚未完成自动验收。已完成范围与剩余验证见 [验证记录](../验证记录.md)。
