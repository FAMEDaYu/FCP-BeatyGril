# 下巴控制与图像坐标核对

2026-10-21，接用户反馈“调整下巴却调整眼睛”。本轮不操作、启动或退出Motion/FCP。以已保存的原版AIR和新REA CPU汇编/常量证据继续分析；没有执行原版或复制其二进制到产品。

## 已确认的下巴差异

参数发布、PGChin=24、settings.faceChin与GPU参数位置没有串到大眼。1.0.5的下巴仍用脸框高斯场，存在两项错误：作用范围延伸到嘴部甚至眼睑，下巴正负方向与原版相反。独立真实照片上，旧公式的最大位移出现在嘴附近；侧脸真实下巴位移接近零。这些结论来自离屏照片/坐标场探针，不能代替实际宿主当帧诊断。

原版`0x1000279f4`汇编将下巴滑块约束到[-1,1]，正值乘0.04、负值乘0.02，写入脸型结构第5项（byte offset20）；常量位于`0x10005f9c0`。REA记录：`ev_8bc31392c07788d2482546121297c3f177d527282275ef21fd3e5edef9921544`与`ev_640ccb714c5ce00d3864844af319fc574d223810dde08443d2ef2e8f1e989c47`，完整小型证据包见[rea-chin.json](rea-chin.json)。原件身份与上一轮一致，arm64切片SHA-256为`f01e8c0b7e2676b2961950b0e48efdd2589af218e4b36de7d39f5d1c76852bfb`。

`mssFaceShapePinCoordinate`的AIR分支读取第5项及共同尺寸增益，顺序执行68→38、67→37、66→36三组局部采样位移。独立Vision区域核对：66/67/68在下巴轮廓，36/37/38在下唇。其半径、线性衰减、逐步clamp与17组瘦脸相同；支持负值。视觉正值缩短下巴、负值拉长，方向随下巴→嘴唇向量变化，不固定沿画面Y轴。细节和边界见[机器报告](chin-report.json)。

## 修正与测试

已移除旧下巴高斯项，改用原版三组点、正负系数、尺寸增益。完整76点缺失或不合法时跳过下巴，避免旧档案使用猜测框位置；其他七类脸型控制仍是现有近似实现，组合顺序未宣称全部恢复。

核心回归559项通过：美化49、人脸116、瘦脸/下巴394。新增正负下巴、半强度、左右侧脸投影、歪头、三种宽高比、非零原点、瘦脸叠加、坏点与旧档案保护。独立double采样场最大UV误差1.09828022e-5。真实NASA人像额外检查下巴位移、正负向量符号和两侧瞳孔保持不动；以坐标位移判定，避免只检查“像素有改变”。

## 图像适配层待核对项

纯CI图像中，76点落在真实瞳孔和下巴，没有全局Y轴反置。但FxPlug适配层曾根据imageOrigin在输入、输出各翻转一次。以相同物理top-first照片字节离屏构造TOP_LEFT输入输出时，旧代码默认直通仍精确一致，却能复现下巴作用到眼部的现象；这说明直通测试无法排除中间处理倒置。

imageOrigin描述坐标轴方向，不能单凭枚举推断IOSurface的物理行序。原版render主入口包装CIImage后仅见正尺度和位移，仍需核对其输出helper，不能仅凭主函数的有界检索宣称原版整个链条无翻转。原生FCP本次实际缓冲行序未捕获，最后视觉交由用户自测。临时照片、完整人脸坐标和探针输出均留在被忽略的build目录。
